# 島の運用案（実装案）

まだ作らない。メイン島 1 つで始め、データの置き方だけ先に島ごとにしておく。

## 0. 前提：データの置き方
```
data/
  islands.json            … 島の一覧（id・名前・特産・人数・上限・開いた日）
  islands/main/           … メイン島（world.json・villagers.json・diary/ など今の中身）
  islands/forest/         … サブ島ができたら同じ形で増える
  routes.json             … 船の便・交易・行き来の予定
  league.json             … 対抗戦の記録
```
- 毎朝の計算（sim）は島ごとに回す。島どうしのやり取り（交易・移住・対抗戦）は、全部の島を回した後にまとめて 1 回だけ計算する。
- サイトは見ている島のフォルダだけを読む。最初の画面は「自分の島」（ログインしていなければメイン島）。

## 1. 島ごとの特産（案 3）
| 島 | 多いもの | 少ないもの |
|---|---|---|
| メイン島 | 平地・畑 | 鉱石 |
| 森の島 | 木・動物 | 石 |
| 鉱山の島 | 石・鉄・金・ダイヤ | 木・畑 |
| 海の島 | 魚・砂・貝 | 鉱石 |
- 地形の生成のしかた（ノイズの設定）を島ごとに変えるだけで作れる（`islands.json` の `biome`）。
- 足りない物があるので、自然に交易が必要になる。

## 2. 交易（船の便）
- 島どうしを船の便で結ぶ。2〜3 日に 1 便。
- 各島のチェストで「余っている物」と「足りない物」を自動で数え、便が来た日に交換する（例：鉱山の島の鉄 10 ↔ 森の島の原木 30）。
- 交換の比率は、物の珍しさで決める（`config.json` の `trade.value`）。
- 交易の日はリールの小ネタになる：「今日の交易：鉄 10 と原木 30」。

## 3. 島の行き来
- 港を建てた島どうしで行き来できる（港は投票で建てる建物）。
- 村人は、
  - **出かける**：仕事や交易についていき、数日で帰ってくる。出先の島で友だちができる。
  - **引っ越す**：プロフィールから「引っ越したい」を出すと、次の便で移る。1 か月に 1 回まで。
- 船は、港と港の間を動く 3D の船として町の画面に映す。乗っている村人も見える。
- 島どうしの関係（友だち）は、同じ便に乗った・出先で会った時だけ育つ。全員どうしを計算しないので軽いまま。

## 4. 島の対抗戦（案 4、人数が集まってから）
- **始める条件**：島が 2 つ以上あり、それぞれ 30 人以上（`config.json` の `league.minPerIsland`）。それまでは出さない。
- **期間**：1 週間（月曜〜日曜）。
- **お題**（毎週ひとつ、リールの投票で決めてもよい。建物づくりはお題にしない）：
  - 陣取り合戦（下の 8 章）
  - 魚をいちばん多く釣る
  - ダイヤをいちばん多く掘る
  - 畑の収穫がいちばん多い
- **点の数え方**：島の人数で割る（人数の多い島が必ず勝たないように）。
- **ごほうび**：勝った島に、記念の像や旗が立つ。その週の交易で少し有利になる。
- **リール**：日曜に結果発表（順位と、各島の名場面を数秒ずつ）。
- 負けた島への罰はなし。

## 5. 新しい島の開き方（案 1・5）
- メイン島が上限（例：1,000 人）に近づいたら、リールの投票で「次はどの島を開く？」（森・鉱山・海）。
- 参加のコメントに島の名前を書けば、その島に住める（例：「参加したい 鉱山島」「参加したい 鉱山島 ピッケル」）。書かなければ、人の少ない島に入る。
- 新しい島は 0 日目から始まり、その島の「パート 1」を作れる。

## 6. リールの投票
- インスタの投票は、いつも 1 問だけ。
  - ふだんはメイン島（または、その日の主役の島）の「何を建てる・どこに建てる」。
  - 島を開く日は「次の島はどこ？」。
  - 対抗戦の週の月曜は「今週のお題は？」。
- サブ島の毎日の選択は、サイトの投票ページで、その島の住人が決める。投票がなければ自動で決まる。

## 8. 陣取り合戦（サイトから参加する対戦）
github.io のサイトはサーバーを持たないので、**1 日 1 回まとめて決着する「手番式」**にする。リアルタイムの撃ち合いではなく、毎日少しずつ陣地を広げる遊び。

### 遊び方
- 島のまわりの海に、6 角形のマス（ヘックス）の「合戦の地図」を置く。マスごとに、どの島（チーム）の陣地かが決まっている。
- ログインした村人は、毎日 **行動ポイント**（AP）をもらう。量はレベルで増える（例：3 + レベル ÷ 5）。
- サイトの「合戦」ページで、自分の島の陣地のとなりのマスに AP を置く。
  - 空いているマス：置いた AP の合計がいちばん多い島が取る。
  - 他の島のマス：守り（そのマスの島が置いた AP＋地形の守り）より多ければ取れる。
- 毎朝の計算（GitHub Actions）で、全員の置いた AP をまとめて一度に決着させる。同時に置くので、先に置いた人が有利にはならない。
- マスには特産がある（鉱石のマス・魚のマスなど）。持っているマスの数に応じて、その島のチェストに毎日少し物が入る。
- 1 シーズン 2 週間。終わったら地図をまっさらに戻す。陣地がいちばん多い島が優勝。
- **合戦は、開いている間だけ表示する。** 合戦の地図・陣地の色・旗・矢印は、町とは別の重ね絵（別のデータ `data/battle.json`）にして、町の地形・木・村人・チェストには何も残さない。シーズンが終わったら重ね絵ごと消して、町はいつもの見た目にすべて戻す。残るのは、ごほうび（経験値の瓶など）と、戦績の記録だけ。

### 仕組み
- AP を置く操作は、Firestore の `battle/{season}/moves/{userHash}` に書く（本人だけが書ける。1 日の上限は firestore.rules で確かめる）。
- 毎朝の計算が moves を読んで決着させ、`data/battle.json`（地図の文字列＝マスごとに島の 1 文字、と結果）に書いて push する。
- 地図も、地形と同じ「1 マス＝1 文字」の文字列で持つ。となりのマスを見るのも速い。
- ログインしていない人や AP を置かなかった人の分は、村人が自動で「となりの弱いマス」に置く（町の自動の動きと同じ考え方）。
- ズル対策：1 日の AP 上限はサーバー側（毎朝の計算）でも数え直し、上限を超えた分は捨てる。

### 島が 1 つしかない時
- メイン島の中で、家や仕事ごとのチーム（例：赤・青・緑・黄の 4 チーム）に分かれて戦う。参加した時に、人の少ないチームに入る。
- 島が増えたら、島どうしの合戦に切り替える。

### リール
- 毎日：その日の地図の変化（色が広がる様子）を 3 秒。
- シーズン最終日：結果発表と、いちばん AP を使った村人の表彰（名前は本人が出してよい場合だけ）。

## 9. 経験値とレベル
- 村人は仕事をすると **経験値（XP）** がたまる。
  | すること | XP |
  |---|---|
  | 木を切る・岩を掘る（1 つ落ちるごと） | 1 |
  | 鉱石（石炭 2・鉄 4・金 8・ダイヤ 20） | 2〜20 |
  | 魚を釣る | 3 |
  | 収穫する | 2 |
  | 道具を作る | 5 |
  | 投票する | 5 |
  | 合戦で AP を置く（1 日 1 回） | 5 |
  | 合戦でマスを取った（参加した人で分ける） | 10 |
- **レベル**：次のレベルまでの XP は、だんだん増える（例：レベル n → n+1 に 20 + 10n）。
- **レベルで増えるもの**
  - 持ち物の枠（今は 3 枠から、レベルと日数で増える。この決まりにつなぐ）
  - 合戦の AP
  - 作れる道具の段階（石はレベル 3、鉄はレベル 8 など。材料もいる）
  - 称号（見習い → 一人前 → 名人 → 島の顔）
- **画面**：村人カードとプロフィールに、レベルと、次のレベルまでの緑のバー（マイクラの経験値バー風）。
- **データ**：`villagers.json` に `xp` と `level`。sim が仕事のたびに足す。今ある「Lv」の表示を、この XP からの計算に置きかえる。

## 10. 作る順番
1. 経験値とレベル（いまの島 1 つでもすぐ使える）
2. 陣取り合戦（島 1 つの間は、チーム戦で始める）
3. データを島ごとのフォルダに分ける（中身はメイン島だけ）
4. 島ごとの特産（地形の設定）
5. 2 つ目の島を開く仕組み（投票・コメントで島を選ぶ）
6. 港と船の便、交易
7. 出かける・引っ越す
8. 島どうしの対抗戦・合戦（2 島がそれぞれ 30 人を超えたら）

## 決めておきたいこと
- メイン島の上限人数（1,000 人が軽さの目安）
- 引っ越しの回数の制限
- 対抗戦のごほうびの中身

## 住人の引っ越し（管理者が消す）
- GitHub の Actions → 左の一覧の「moveout」→ 右の「Run workflow」→ username にユーザー名（@ なしでよい）か村人の id を入れる。
- dry にチェックが入ったまま（既定）だと、消すものの一覧をログに出すだけ。チェックを外して動かすと本当に引っ越しさせ、変わった data をコミットする。
- 手元なら `node tools/moveout.js <ユーザー名か id> --dry`（`--dry` をとると書く）。
- 村人・暮らし・日記・関係・手紙などからその人を消し、家・畑・土地は空きにもどす。歴史には「〇〇さんが島を引っ越した。」を 1 行足す（名前をかくしている人はあだ名）。
- 引っ越す前の「住みたい」コメントでは住み直さない（data/moved.json）。あとで新しく「住みたい」と書けば、ふつうに新しく住める。
- Cloudflare の KV（?me= の専用リンクなど）はさわらないので、必要なら別に消す。
