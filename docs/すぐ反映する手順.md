# コメントを 2〜3 分で町に反映する手順

今は 15 分ごと（混んでいると 30 分ごと）にコメントを読んでいます。
この手順をすると、インスタにコメントがついた時に、すぐ町の受付（join）が動きます。

```
インスタにコメント → Meta が知らせる → Cloudflare の受け口 → GitHub の join → サイト
```

- お金はかかりません（Cloudflare Workers の無料の枠・GitHub Actions の無料の枠）。
- ログインや合言葉・鍵を入れるのは、ぜんぶ自分で行います。合言葉・鍵はファイルに書かず、画面の入れる欄にだけ入れます。
- やめたくなったら、Meta の Webhook を外すか、Cloudflare の Worker を消すだけ。15 分ごとの受付はそのまま動きます。

---

## 0. はじめに：どちらのログインか見る

インスタの鍵（GitHub の Secrets の `IG_TOKEN`）の、最初の 2 文字で決まります。

- **`IG` で始まる** → 「インスタのログイン」（Instagram API with Instagram Login）
- **`EAA` などそれ以外** → 「Facebook のログイン」（Instagram API with Facebook Login。Facebook ページとつないでいる）

Secrets の中身は GitHub では見られないので、鍵を作った時のメモで確かめてください。わからない時は、下の手順 5 の「両方の欄」を見て、出てくる方をします。

---

## 1. GitHub の「join を動かす鍵」を作る

1. github.com にログイン → 右上の顔のアイコン → **Settings**。
2. 左の一番下 **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**。
3. 次のようにする：
   - Token name：`town-webhook`
   - Expiration：1 年（切れたら作り直して、手順 4 の `GH_DISPATCH_TOKEN` を入れ直す）
   - Resource owner：`hajimarijima`
   - Repository access：**Only select repositories** → `hajimarijima/hajimarijima.github.io` だけ
   - Permissions → Repository permissions → **Contents** を **Read and write**（ほかは触らない）
4. **Generate token** → 出てきた文字をコピー（1 回しか見られない）。手順 4 で使うまで、メモ帳などに一時的に置き、使ったら消す。

---

## 2. Cloudflare のアカウントを作る（無料）

1. https://dash.cloudflare.com/sign-up でメールとパスワードを入れて作る。
2. 届いたメールで確かめる。プランを聞かれたら **Free**。お店のサイト（ドメイン）は追加しなくてよい。

---

## 3. 受け口（Worker）を置く（コピペ）

1. Cloudflare の画面の左 **Workers & Pages**（「Compute」の中のこともある）→ **Create** → **Create Worker**（「Start with Hello World!」）。
2. 名前を `town-webhook` にして **Deploy**。
3. **Edit code** を押す。左に `worker.js` が出る。中身を全部消して、このリポジトリの **`tools/webhook/worker.mjs` の中身をまるごと貼る**。
   （GitHub のサイトでファイルを開き、右上の「Copy raw file」のボタンでコピーできます）
4. 右上の **Deploy**。
5. 出てきた URL（`https://town-webhook.〇〇.workers.dev`）をメモ。ブラウザで開いて「はじまり島の受け口です（動いています）」と出れば OK。

### 3-2. KV（おすすめ。続けて来たコメントで何度も動かさないため）

1. 左の **Storage & Databases** → **KV** → **Create**（Create a namespace）→ 名前 `town-kv` → Add。
2. Worker（town-webhook）を開く → **Settings** → **Bindings** → **Add** → **KV namespace**。
   - Variable name：`TOWN_KV`
   - KV namespace：`town-kv`
   → **Deploy**（または Save）。

---

## 4. Worker に合言葉・鍵を入れる（Secrets）

Worker（town-webhook）→ **Settings** → **Variables and Secrets** → **Add**。
**Type は「Secret」** にして、下の名前で 1 つずつ入れます（名前はこのとおり、値は自分で入れる）。

| 名前 | 入れる値 |
|---|---|
| `META_VERIFY_TOKEN` | 自分で決めた合言葉（英数字で 20 字くらい。手順 5 でも同じものを入れる） |
| `META_APP_SECRET` | Meta for Developers → 自分のアプリ → **App settings（アプリの設定）→ Basic（ベーシック）** → **App secret** の「Show」で出る文字 |
| `IG_APP_SECRET` | 「インスタのログイン」の時だけ：アプリ → **Instagram** → **API setup with Instagram login** → **Business login settings** の **Instagram app secret** |
| `GH_DISPATCH_TOKEN` | 手順 1 でコピーした文字 |

入れ終わったら **Deploy**。

---

## 5. Meta に受け口を教える（Webhook）

developers.facebook.com → **My Apps** → 町のアプリ。

### 「インスタのログイン」の時

1. 左の **Instagram** → **API setup with Instagram login** → **3. Configure webhooks**（Webhook を設定）。
2. **Callback URL**：手順 3 の Worker の URL。**Verify token**：手順 4 の `META_VERIFY_TOKEN` と同じ合言葉。→ **Verify and save**。
3. 下の Webhook fields（フィールド）で **comments** の **Subscribe** をオン（ライブ配信のコメントも拾うなら **live_comments** も）。

### 「Facebook のログイン」の時

1. 左の **Add product**（製品を追加）→ **Webhooks** → Set up。
2. 上の選ぶ欄で **Instagram** を選ぶ → **Subscribe to this object**。
3. **Callback URL**：Worker の URL。**Verify token**：同じ合言葉。→ **Verify and save**。
4. 出てきた一覧の **comments** の **Subscribe** を押す（**live_comments** も任意）。
5. インスタの鍵に `pages_manage_metadata` の権限が要ります。足りない時は Graph API エクスプローラで、この権限も付けて鍵を作り直し、GitHub の Secrets の `IG_TOKEN` を貼りかえてください。

### 両方共通：アカウントでオンにする

1. GitHub → このリポジトリ → **Actions** → **ig-check** → **Run workflow** → 「すること」で **webhook をオンにする** を選んで Run。
2. 緑になって、ログに「Webhook（comments）をオンにしました」か「Facebook ページ「…」で Webhook をオンにしました」と出れば OK。

### 大事：Meta の決まり

- Meta の説明では、本物のコメントの知らせは **アプリが「公開（Live）」** の時だけ届きます。アプリの画面の上の「開発中（Development）」を **Live** にします（プライバシーポリシーの URL などを聞かれます）。
- さらに Meta の説明では、`comments` の Webhook には **Advanced Access（アプリ審査とビジネスの確認）** が要る、とあります。審査が済むまでは、自分のアカウントでも届かないことがあります。
- インスタのアカウントは **公開**（鍵なし）である必要があります。
- 届かない時は、下の「6. 届かない時の代わり」を使えば、審査なしで同じくらい速くなります。

---

## 6. 届かない時の代わり：2 分ごとの見回り（審査いらない）

Worker が 2 分ごとに「最近の投稿のコメントの数」だけ見て、増えていたら join を動かします（インスタの API は 1 時間に 30 回）。

1. 手順 3-2 の KV を必ず付ける。
2. Worker → **Settings** → **Variables and Secrets** に Secret を 2 つ足す：
   - `IG_TOKEN`：GitHub の Secrets と同じインスタの鍵
   - `IG_USER_ID`：GitHub の Secrets と同じアカウントの ID
3. Worker → **Settings** → **Trigger Events**（または Triggers）→ **Add** → **Cron Triggers** → 「Cron expression」に `*/2 * * * *` → Add。

この見回りは、**フォロワー数** も 2 分ごとに読みます（下の 6-2）。

### 6-2. フォロワー数を 2〜3 分ごとにサイトに出す

GitHub の時間の実行は 5 分より短くできないので、フォロワー数は Worker が 2 分ごとに読んで覚えておき、サイトがそれを読みます。

1. 上の 1〜3（KV・`IG_TOKEN`・`IG_USER_ID`・Cron）をしておく。フォロワー数だけでよければ `GH_DISPATCH_TOKEN` はなくても動きます。
2. 数分待ってから、ブラウザで `Worker の URL/stats`（例 `https://town-webhook.〇〇.workers.dev/stats`）を開き、`{"followers":123,"at":"…"}` と出るのを確かめる（最初の 2 分は `{}`）。
3. **Worker を作ったら、その URL をサイトに教える**：GitHub でこのリポジトリの `data/config.json` を開き、鉛筆のボタン →
   `"liveStatsUrl": ""` の `""` の中に、2 の URL（`/stats` まで）を入れて **Commit changes**。
4. 投票のページの「今のフォロワー」が、2〜3 分ごとの数になります。Worker が止まっていても、15 分ごとの受付で書いた数がそのまま出ます。

- このアドレスが読めるのは、町のサイト（`https://hajimarijima.github.io`）のページからだけです（ほかのサイトからは読めない）。返すのはフォロワー数と時刻だけです。

注意：インスタの鍵は 60 日で切れます。Actions のログに「鍵が新しくなりました」と出たら、GitHub の Secrets と、ここの `IG_TOKEN` の **両方** を貼りかえてください。

---

## 7. ためす

1. ブラウザで Worker の URL を開き、「動いています」と出る。
2. Meta のアプリ → Webhooks（またはインスタのログインの Configure webhooks）→ **comments** の **Test**（テスト）→ **Send to My Server**。
3. Cloudflare の Worker → **Logs**（Observability / Real-time logs）に「join を動かしました」と出る。
4. GitHub → **Actions** → **join** に、`repository_dispatch` で動いたものが 1 つ増える（緑になれば OK。テストの知らせは本物のコメントではないので、村人は増えません）。
5. 本番：自分のではないアカウントで、どれかの最近の投稿に「住みたい」とコメント → 2〜3 分で町のサイトに出る。

うまくいかない時：
- Cloudflare のログに「署名が合いません」→ `META_APP_SECRET`（インスタのログインなら `IG_APP_SECRET` も）の値を見直す。
- 「GitHub に頼めませんでした 401/403/404」→ 手順 1 の鍵（リポジトリの選び方・Contents の Read and write）を見直す。
- Meta の「Verify and save」で失敗 → Worker の URL と `META_VERIFY_TOKEN` が同じか見る。

## かかる時間の目安

| ところ | 時間 |
|---|---|
| コメント → Meta の知らせ → Worker | ふつう数秒（たまに数分） |
| Worker → GitHub の join が動き始める | 10〜60 秒 |
| join の中身（準備・インスタを読む・受付・コミット） | 30〜60 秒 |
| GitHub Pages がサイトを作り直す | 30〜90 秒 |
| **合計** | **ふつう 1 分半〜3 分**（2 分ごとの見回りなら +0〜2 分） |

- GitHub が混んでいる時は 5〜10 分かかることもあります。
- 毎朝の daily が動いている間は、それが終わるまで待ちます。
- コメントが続けて来ても、join は「動いている 1 つ＋待っている 1 つ」だけ。待っている方は最新のコメントまで読みます（Actions の一覧に「Cancelled」が出ることがありますが、それで正しい動きです）。

## インスタの API の使う量（1 時間に約 200 回まで）

- join 1 回：投稿の一覧 1 回 ＋ フォロワー数 1 回 ＋ 投票の投稿のコメント（50 件ごとに 1 回）＋ コメントの数が変わった投稿だけ（50 件ごとに 1 回）。ふつう 3〜5 回。
  フォロワー数は毎回 1 回（サイトの数が 15 分ごとに新しくなる）、鍵ののばしは 1 日 1 回。Worker の見回りは 2 分に 1 回（1 時間 30 回）。6 時間に 1 回は最近の投稿（25 件）をぜんぶ読み直します（〜30 回）。
- コメントがどんどん来ても、join は 1 時間に 40 回くらいまで（1 回 1〜2 分かかるので）→ 多くて 1 時間 100〜160 回。
- 毎朝の daily は、最近の投稿をぜんぶ読みます（〜30 回、1 日 1 回）。
- 読む投稿の数は `data/config.json` の `joinScanPosts`（既定 25）と `joinScanDays`（既定 60 日）で変えられます。
