# みんなで町づくり

インスタの参加者が村人になって、毎日すこしずつ町を育てる静的サイトです。
GitHub Pages（`○○.github.io`）にこのフォルダの中身をそのまま置けば動きます（ビルド不要）。

## 中身

## 手元で見る

```
npm install          # http-server（静的サーバー）だけ入る
npm run serve        # http://localhost:8090
```

## よく使うこと

```
node tools/init.js           # 本番の 0 日目に戻す（木と岩だけ・村人 0）。公開する時はこの状態から
node tools/sim.js            # 1 日進める（--days 7 で 7 日）
npm run demo                 # 見本の村人 20 人で 30 日進める（data/ が見本で上書きされるので、公開前に init.js で戻す）
npm run skins                # スキンを作り直す
npm test                     # 参加の登録・投票の集計・取り込みなどのテスト
```

乱数は `state.json` の `seed` と日付で決まるので、同じ入力なら同じ町になります。

## 町の決まり

- 村人は毎日「木を切る（木材）」「岩を掘る（石）」「草や実を集める・畑を耕す（食べ物）」のどれかをします。次に建てる物に足りない資源ほど選ばれやすく、人ごとに好きな仕事もあります。
- 切った木は切り株になり、5〜8 日で若木を経てまた生えます。岩は掘るたびに小さくなり、最後は石切り場の跡になります。石が少なくなると新しい岩場が見つかります。
- 資源がたまると `config.json` の順番（小屋 → 家 → 作業場 → 店 → 倉庫 → 広場 …）で 1 日 1 つ建ちます。家がない人はたき火のそばのテントで寝ます。
- フォロワーが 10・25・50・100・300・1000 人…に届くと 3 日間の投票が開き、選ばれた建物とその先の建物が順番に入ります（分岐）。序盤（10 人：井戸 / 倉庫 / 木の柵、25 人：作業場 / 見張り台 / 菜園）は普通の村の建物だけで、温泉・時計台・港などの特別な建物は 50 人からです。

### 木と岩をブロックで採る

- 岩は小さなブロックの積み重ね（下 3×3・中 2×2・上 1）で、上から 1 つずつ掘ります。たたくたびにひびが 10 段階で入り、かけらが飛び、少し縮んでから消えます。掘り終えた所は土のくぼみになります。
- 岩の中身（石・石炭・鉄・金・ダイヤ）は `data/config.json` の `ores` の確率と、種と岩の id で決まります（毎回同じ）。深い所ほど鉱石が出やすく、鉄・金・ダイヤを掘ると光り、歴史に「〇〇が鉄鉱石を見つけた。」と残ります。
- 木は下から 1 本ずつ切り、まれにリンゴや苗が落ちます。落ちた原木・丸石・鉱石はゆっくり回り、拾うと「+1」が出て、倉庫に置くと山が高くなります。
- 地図は一辺がおよそ 2 倍（220）で、町の外にも森と岩場が続きます。遠くの木と手つかずの岩はまとめて描く（インスタンス）ので、スマホでも重くなりません。
- 見本のデータの名前は「村人1」「村人2」…で、本当の ID にはなりえない形です。動画には名前を出しません（本物の参加者の名前は今までどおりサイトに出ます）。

## 昼と夜・夜の敵

- 町の地図は、本当の時刻（日本時間）に合わせて朝・昼・夕方・夜が変わります（空の色・太陽と月・星・光の向きと影）。夜は家の窓・扉の横のたいまつ・街灯が光ります。
- 夜、村人は家（家がない人はテント）に帰って寝ます。何人かは町のはずれで、たいまつを持って見張りをします。
- 確かめる時は `?time=morning`・`?time=day`・`?time=evening`・`?time=night`、または `?time=21:30` のように時刻を付けて開きます（例 `index.html?time=night`）。
- 2 日目の夜から、森の外からゾンビ・スケルトン・クモが来ることがあります。結果は `tools/night.js` が決めて `data/state.json` の `night` と歴史（「夜」）に残します。例：「3日目の夜、ゾンビ 2 体とスケルトン 1 体が来たが、村人1たちが追い払った。」
- ゾンビは破れた服の箱人形で、腕を前に出してよろよろ歩きます。スケルトンは弓を持ち、少し離れて止まって矢を射ます。矢は柵や地面に刺さり、見張りは盾で防ぎます。
- 見張りの力（1 人 2）＋守りの建物の強さ＋たいまつが、来た数より足りないと、小さな被害が出ます（畑がひとつ荒らされる・倉庫の食べ物が少し減る・見張りが軽いケガをして次の日だけ休む）。村人は死にません。朝になるとゾンビは燃え、ほかは森へ帰ります。
- 守りの建物：木の柵（2）・石の壁（4）・見張り台（2）・街灯（1）・見張り塔（3）。合計が大きいほど、静かな夜がふえ、来る数が減ります。木の柵は 10 人、見張り台は 25 人、石の壁・街灯は 100 人の投票で選べ、選ばなかった物もあとで建ちます。
- 夜の乱数は昼とは別なので、夜を足しても昼の仕事・投票・関係の流れは変わりません（ケガで休んだ次の日からは変わります）。

## 最初の日

本番の 0 日目は、木と岩だけの平地です（村人 0 人・建物 0・道 0。たき火もありません）。最初に「参加したい」とコメントした人が、最初の村人になります。
村人が 0 人の間は、どの画面にも「まだだれもいません。コメントに『参加したい』で最初の村人に」と出ます。

## 参加の登録（コメント）

- 投稿に「参加したい」「参加します」「参加」を含むコメントをした人が、次に `sim.js` が動いた日から村人になります（言葉は `config.json` の `joinWord`）。
- 前の言葉「住民登録」も、念のため読みます。「参加しない」「参加できない」「不参加」は登録にしません。
- 同じ人が何回コメントしても 1 回だけ。見分けはコメントの `from.id`（インスタの固定の ID）です。
- 名前（username）が変わっていたら、名前だけ新しくします。参加日やスキンはそのままです。
- スキンは村人の番号から決まるので、名前が変わっても見た目は変わりません。
- インスタの ID と名前は、そのままではなく印（sha256）にして `villagers.json` に入れます。

## 投票（コメント）

- 投票中の投稿へのコメントから A・B・C を読みます。全角（Ａ）、小文字（a）、「Aがいい」「B案」も読みます。「BとCで迷う」のように 2 つ書いたものは数えません。
- 1 人 1 票で、何度か書いた人は最後のコメントだけ数えます。締め切りの時刻（`state.json` の `vote.closesAt`）より後のコメントは数えません。
- 手で票を足したい時は `state.json` の `vote.manual` に `{"A": 3, "B": 0, "C": 1}` のように書きます（コメントの票に足されます）。
- 結果は `state.json` の `decisions` と `history.json` に残り、投票のページに割合の棒グラフ、投票した人数、時間ごとの伸び（折れ線）、過去の結果が出ます。

## フォロワー一覧の取り込み

インスタの公式 API ではフォロワーの一覧は取れません。代わりに、アカウントの持ち主が自分の情報をダウンロードして取り込めます。

1. インスタのアプリで「設定とアクティビティ」→「アカウントセンター」→「あなたの情報とアクセス許可」→「個人情報をダウンロード」を開く。
2. 「情報をダウンロードまたは転送」→ インスタのアカウントを選ぶ →「一部の情報」→「フォロワーとフォロー中」だけにチェック。
3. 「デバイスにダウンロード」で、形式は **JSON**、期間は「全期間」にしてリクエストする。
4. 準備ができるとメールが届く（数分〜数日）。zip を開くと `connections/followers_and_following/followers_1.json` がある。
5. それを `data/import/` に置いて `node tools/import_followers.js` を動かす。まだいない人だけが次の日から村人になります（名前で見分けるので、何度取り込んでも重複しません）。

`data/import/` と `data/inbox/` は全員の名前が入るので、`.gitignore` で GitHub に上がらないようにしてあります。

## 名前を出したくない人

```
node tools/hide.js ユーザー名
```

`data/hidden.json` に名前から作った印（`sha256:…`）が書かれ、その人は「のんびりなタヌキ」のような自動のあだ名で表示されます。`villagers.json` からも名前が消えます。`hidden.json` に名前をそのまま書いても動きますが、公開されるので印にするのがおすすめです。

## GitHub に出す

1. GitHub で新しいリポジトリを作る（例：`minna-no-machi`。`ユーザー名.github.io` にすればトップの URL になる）。
2. このフォルダ（`town/`）の中身をリポジトリのいちばん上に置いて push する（`node_modules/` は `.gitignore` 済み）。
3. リポジトリの Settings → Pages →「Deploy from a branch」→ `main` / `/(root)` を選ぶ。
4. 本番を始める時は `node tools/init.js` で村人なしの 0 日目に戻してから push する（見本のままでもよい）。`data/config.json` の `account` を自分のアカウント名にする。

## インスタとつなぐ（GitHub Actions で毎日動かす）

`.github/workflows/daily.yml` が下書きです。今は手で動かす時だけ動きます。

1. インスタを **プロのアカウント（ビジネス or クリエイター）** にし、Facebook ページとつなぐ。
2. Meta for Developers でアプリを作り、「Instagram Graph API」を足す。権限は `instagram_basic`、`instagram_manage_comments`、`pages_show_list`、`pages_read_engagement`。
3. Graph API エクスプローラで、つないだインスタの ID（`IG_USER_ID`）と長期アクセストークン（`IG_TOKEN`、60 日で切れるので更新が要る）を取る。
4. 「参加したい」を集める投稿の ID（`IG_JOIN_MEDIA`、複数ならカンマ区切り）と、今の投票の投稿の ID（`IG_VOTE_MEDIA`）を調べる（`/{IG_USER_ID}/media` で一覧が出る）。
5. GitHub のリポジトリの Settings → Secrets and variables → Actions に、上の 4 つを入れる。合言葉はファイルに書かない。
6. Actions タブから daily を手で 1 回動かして、町が 1 日進むか見る。よければ `daily.yml` の `schedule` の `#` を外す。

投票が開いたら（投票のページに出る）、その投稿を作って `IG_VOTE_MEDIA` をその投稿の ID に変えます。

## Google ログイン（プロフィールを自分で書きかえる）

村人ページの「プロフィール」で、Google でログインした本人だけが自分の村人のプロフィールを書きかえられます。Firebase Authentication と Firestore の無料枠で動きます。`js/firebase-config.js` が空のあいだは、ボタンが「Google でログイン（準備中）」になるだけで、サイトはそのまま動きます。

**保存するもの**：Google アカウントの `uid` と、結びつけた村人の key だけ。メールアドレスや名前は読みこまず、保存も公開もしません。

### つなぎ方 1（主）：DM の招待リンク

Instagram のログイン API は、プロの（ビジネス・クリエイターの）アカウントしか使えません。普通の人に Instagram でログインしてもらって名前を受け取ることはできず、Google ログインからインスタの名前を知ることもできません。そこで、コメントした人に DM でリンクを送ります。

1. 「参加したい」とコメントする。
2. 毎日の処理で村人になったあと、`tools/firestore_sync.js` がその人専用の招待の印（20 字・7 日で切れる・1 回だけ）を Firestore の `invites` に作り、Instagram の **Private Replies**（コメントした人に 1 回だけ DM を送れる仕組み）でリンク（`villager.html?k=村人&invite=印`）を送る。
3. リンクを開いて Google でログインすると、コードを打たずにそのまま村人とつながる（使った印は毎日の処理が消す）。

要るもの・注意：
- 権限 `instagram_manage_comments` と `instagram_manage_messages`。どちらも **Meta のアプリ審査** が要ります。
- Private Replies は、コメントから 7 日以内に、1 つのコメントへ 1 回だけ送れます。
- `config.json` の `siteUrl` に公開したサイトの URL を入れる（リンクに使う）。
- いまは `tools/instagram.js` の `sendPrivateReply` は形だけで、本物の API にはつないでいません（`DM_READY = false`）。審査が済んだら `DM_READY` を `true` にし、中の fetch の行を戻してください。
- DM を送れない時や、審査が済むまでの間は、下の「つなぐ」コードの方法を使います。
- 処理は毎日の更新に入っています。DM を早く届けたい時は、daily を数分おきに動かす別のワークフローを足してもよいです（村人になるのは `sim.js` が動いた時なので、そのあとに送られます）。

### つなぎ方 2（予備）：「つなぐ」コード

1. 村人ページで「Google でログイン」を押す。
2. 一度だけ使える短いコード（例「つなぐ 7K3Q」）が出るので、コピーして **インスタの「参加したい」の投稿にコメント** する。
3. 次の毎日の処理で、コメントした人の `from.id` が参加の登録をした人と同じかを確かめ、その Google アカウントと村人を結びつける（コードは消す）。
4. それからは、ログインすると入力欄が出て「保存」できる。次の毎日の処理で町に反映される。

ほかの人のコードをコメントしても、コメントした本人の村人に結びつくだけなので、他人の村人は乗っ取れません。1 つの村人に結びつくのは最後の 1 人だけです。

### 用意（最初に 1 回）

1. https://console.firebase.google.com/ でプロジェクトを作る（Google アナリティクスは不要）。
2. 「Authentication」→「ログイン方法」で **Google** を有効にする。「設定」→「承認済みドメイン」に GitHub Pages のドメイン（`ユーザー名.github.io`）を足す。
3. 「Firestore Database」を作る（本番モード、場所は `asia-northeast1` など）。
4. 「ルール」に、このリポジトリの `firestore.rules` の中身を貼って公開する（または `npx firebase-tools deploy --only firestore:rules`）。
5. 「プロジェクトの設定」→「マイアプリ」でウェブアプリを足し、出てきた `apiKey` / `authDomain` / `projectId` / `appId` を `js/firebase-config.js` に入れる。これらは公開されても大丈夫な値です（守りはルールで行います）。
6. 「プロジェクトの設定」→「サービス アカウント」→「新しい秘密鍵を生成」で JSON をダウンロードし、**中身をそのまま** GitHub の Secrets に `FIREBASE_SERVICE_ACCOUNT` という名前で入れる。ファイルはリポジトリに入れず、入れたら手元からも消す。
7. Actions の daily を手で動かすと、`tools/firestore_sync.js` が「つなぐ」コメントを処理し、プロフィールを `data/villagers.json` に入れる。手元で試すなら `FIREBASE_SERVICE_ACCOUNT='（JSON）' node tools/firestore_sync.js --dry`（書きこまずに結果だけ出す）。

### プロフィールの項目（`data/config.json` の `profileFields`）

項目は定義から入力欄と表示を自動で作ります。1 つの項目に書けるもの：

| キー | 意味 |
| --- | --- |
| `id` / `label` | 項目の名前と、画面に出す名前 |
| `type` | `select`（`options` から選ぶ）・`text`・`number`（`min` / `max`）・`monthday`（月日）・`date`・`color` |
| `public` | `true` なら村人ページに出す。`false` なら本人だけが見られ、`data/` には入れない |
| `effect` | 町への効き方。`personality`（性格・相性）・`birthday`（お祝い）・`accent`（服の差し色）・`job`（仕事の割り当て） |
| `max` | 文字の上限（`text`） |

自由に書ける欄は、悪い言葉・リンク・@ を弾き（`js/profile-fields.js`）、ページに出す前に必ずエスケープします。毎日の処理でも同じ確かめをもう一度してから反映します。

**項目を足したり変えたりしたら、`firestore.rules` の `profiles` の `hasOnly([...])` と各項目の確かめも合わせて直してください。**（公開しない項目は `private` の `hasOnly` に足す）

### 予備：コメントで送る

ログインを使わなくても、村人ページの「コメントで送る」で「プロフ INFP 0512」のような文を作り、「参加したい」の投稿にコメントすれば、MBTI と誕生日（月日）だけは反映されます。`config.json` の `profileForm.url` に Google フォームなどの送り先（`{text}` が文に置きかわる）を入れると、フォームへのボタンも出ます。

## スキンについて

`tools/gen_skins.js` が髪型・髪色・肌・目・眉・口・服（シャツ・上着・ズボン・靴）・小物（帽子・めがね・エプロン・マフラー・うで時計）を組み合わせて、64×64（マイクラのスキンと同じ配置）で作ります。既存のスキンは使っていません。
