# はじまり島

フォロワーといっしょに作る島づくり。インスタでフォローして「住みたい」とコメントした人が、すぐ村人になって、毎日すこしずつ町を育てる静的サイトです。
GitHub Pages（`○○.github.io`）にこのフォルダの中身をそのまま置けば動きます（ビルド不要）。

## 中身

## 手元で見る

```
npm install          # http-server（静的サーバー）だけ入る
npm run serve        # http://localhost:8090
```

## よく使うこと

```
node tools/init.js           # 本番の 0 日目に戻す（木と岩だけ・村人 0）。公開する時はこの状態から
node tools/sim.js            # 1 日進める（--days 7 で 7 日。手で動かす時は 0 日目でも進む）
node tools/join.js           # 「住みたい」の受付と、その場の入居（日は進めない）
npm run demo                 # 見本の村人 20 人で 30 日進める（data/ が見本で上書きされるので、公開前に init.js で戻す）
npm run skins                # スキンを作り直す
npm test                     # 参加の登録・投票の集計・取り込みなどのテスト
```

乱数は `state.json` の `seed` と日付で決まるので、同じ入力なら同じ町になります。

## 町の決まり

- 村人は毎日「木を切る」「岩を掘る」「草や実を集める・畑を耕す」のどれかをします。集めた物は、その日の終わりに村のまん中の「町のチェスト」に入ります。建てる時や食べる時は、チェストから使います。サイトの「町のチェスト」で今の中身が見られます（地図のチェストの札を押すと飛びます）。
- 1 日目は、まず村のまん中の草と小石をどけて地面をならします（整地）。チェストもこの日に置きます。

### 何をどこに建てるかは、ぜんぶ投票

- 村人がいて、建てている物がない時は、「何を建てる？」（9〜15 時）と「どこに建てる？」（15〜24 時）の 2 つの投票が A/B/C で開き、次の日の朝に決まります（時間は `config.json` の `buildVote`）。
- 最初の候補は「A 小屋 / B 倉庫 / C 作業台」（`firstChoices`）。そのあとは `choicePool` の順に 3 つずつ出ます。場所の候補は「海のそば」「〇の森の入口」「広場の近く」などで、地図に A/B/C の旗が立ちます。
- 場所が決まると、そこをならして（木はどけ、岩は掘り出す）建て始めます。地図には足場と「建てている：〇〇」の札が出ます。材料がチェストにそろうと建ちます。
- フォロワーが 50・100・300・1000・3000・10000 人に届くと、温泉・時計台・港などの特別な建物が候補に入ります（`milestones` の `adds`）。
- 作業台があると、ときどき（`crafting.toolVoteEvery` 日ごと）「どの道具を作る？」の投票も開きます。

### 道具作り

- 道具は つるはし・斧・シャベル・くわ・剣・釣りざお の 6 種類で、素材は 木・石・鉄・金・ダイヤ の 5 つ（レシピ 30 個）。柄は茶色の棒を斜めに、頭は素材の色で、木は明るい板の色、石は暗い灰色、鉄は白に近い銀、金は黄色、ダイヤは水色にしています（アイコンは `tools/gen_icons.js` で作る 16×16 のドット絵、一覧は `video/道具一覧.png`）。
- 道具は 木 → 石 → 鉄 の順に良くなります（金は早いがこわれやすく、ダイヤは一番）。素手より木、木より石が、少ない回数で取れ、多く落ち、長持ちします（`crafting.tiers` の `hits`・`drop`・`durability`）。
- レシピは `crafting.recipes`。例：木のつるはし＝板 3＋棒 2、石のつるはし＝丸石 3＋棒 2（作業台がいる）、鉄のつるはし＝鉄鉱石 3＋石炭 1＋棒 2（作業台がいる）。板と棒は原木から自動で作ります（原木 1 → 板 4、板 2 → 棒 4）。
- 材料が足りない時は、日記に「木の斧を作りたかったが、材料が足りない（原木 あと 2）」のように残り、素手でがんばります。こわれた道具は、材料があれば作り直します。

### 鍛冶屋と防具（`config.json` の `smithing`、`js/smithing.js`）

- 作業台と倉庫が建って 6 日目をすぎると、「鍛冶屋」が「何を建てる？」の候補に入ります。建つまでは、だれも鍛冶をしません。
- 鍛冶屋が建った次の日から、石をいちばん多く集めた人が鍛冶職人（仕事「鍛冶」）になります（`state.json` の `smiths`）。昼に鍛冶屋の金床で金づちをふるい（時間の記号 `sm`）、チェストの材料で、ほかの村人の道具を良い物に作り直したり、防具（帽子・服・くつ）を作ったりします。1 日 2 個まで。見張り（剣を持つ人）が先、そのあとは段階の低い人から。作る物がない日はふつうの仕事をします。
- 防具は 羊毛（羊毛 2〜4）・革（まだ手に入らないので作れない）・鉄（鉄鉱石＋石炭）。持ち物の枠は使わず、村人の `life.json` の `gear` に入ります。村人ページとカードに「装備：鉄のつるはし・羊毛の服…」、町の姿にも帽子（てっぺんとつばだけ。顔と髪は見える）・服・くつの色が重なります。
- 防具は夜の敵の攻撃を少しへらします（守りの合計 × `combat.armorPerDef` の確率で 1 へる）。

### 木と岩

- 岩はひとかたまりの大きな岩です。決まった回数（素手 8・木 6・石 4・鉄 3 回）たたくと 1 つ落ちます。たたいている間に小さくなったり、ひびが入ったりはしません。掘り切るとくだけて消えます。
- 木も同じで、決まった回数たたくと倒れて原木が落ち、切り株が残ります（途中で縮んだり消えたりしません）。
- 大きさは村人が約 2 ブロック（1 ブロック＝村人の背の半分）。木は幹 5 ブロック＋葉の塊で、人よりずっと高くしています。岩は石と鉱石のブロックを 3×3・2×2・1 に積んだ形です。
- 木が倒れる時は、根元を軸にゆっくり傾き始めてだんだん速く倒れ、地面で少し弾んでから葉を散らして消えます（切り株は残る）。
- 町のチェストは、茶色の木箱に黒い縁と前の錠が付いた形で、ふたは後ろのちょうつがいで開きます。

### 釣り・畑・動物

- 釣り：池のそばで釣りざおを投げ、うきが沈んだら釣り上げます。魚はフナ・ニジマス・コイ・ナマズ。まれに宝物（古い金貨・真珠）やがらくた（古い長ぐつ・流木）。確率は `config.json` の `fishing`（`biteChance`・魚の重み・`treasure.p`・`junk.p`）。
- 魚の大きさ：釣った魚は大きさ（cm）がいろいろで、魚ごとの範囲（`fishing.sizes` の `min`〜`max`、まれに `bigMax` までの「大物」）の中で決まります。大きいほど出にくくしています（`skew`・`bigP`）。記録は魚ごとの上位 `rankKeep` 匹（`state.json` の `fishing`）と、村人ごとの魚ごとの一番（`life.json` の `fishBest`）だけ残します。上のメニューの「釣り」（`fish.html`）が釣りランキングで、村人ページにも一番大きな魚が出ます。島の記録をこえると、歴史に「〇〇が 52cm のコイを釣った！ 島の新記録」、日記にも残ります。町の画面では、釣り上げたあと約 3 秒、その日に釣った魚を順に持ち上げて見せ、頭の上に「フナ 23cm」と出ます（島の新記録の魚は「新記録！」ときらきら）。魚の模型の長さは cm に合わせます（村人の背を約 170cm として）。50cm より小さい魚は右手の指先で尾をつまんで下げ、大きい魚は両腕を前に出して腕の上にのせて抱えます。2 頭身は腕が短いので、魚を小さめにして片手で下げます（`js/character.js` の `showfish`）。村人カードと村人ページに「いちばんの大物：コイ 59cm」も出ます。

魚は 16 種。池（フナ・ニジマス・コイ・ナマズ・ドジョウ・ブルーギル・ウグイ）と、島の町だけの海べ（アジ・サバ・メバル・カサゴ・タイ・ごくまれなマグロ）があり、夜は池でホタルメダカ・ツキウナギ、海べでメバル・ホシアカリが釣れる。釣りの日にどちらへ行くかは村人と日で決まる（config.json の fishing.seaShare、池がない島はいつも海べ）。海べの釣り場は町の画面で島のふちに作り、うきは沖へ投げる。魚の絵は `ICONS_ONLY=fish_ node tools/gen_icons.js` で魚だけ作り直せる（FISH_SHEET=パス で見本も書く）。
- バッジ：上のメニューの「バッジ」（`badges.html`）に、全部のバッジと持っている人が出ます（まだだれも持っていないものは灰色で、もらい方つき）。称号バッジ（`config.json` の `titles`。リボンつきのメダル。はじまりの村人・釣り名人・大物ハンター・りんご好き・橋の大工・マイホーム・古株・人気者）は 1 人 1 回だけで、`tools/titles.js` が毎日自動でおくり、町の歴史と日記に書きます。もらう数（`n`）や名前・説明は `titles` の中で変えられ、足し方は `titles.note` に書いてあります。絵は `node tools/gen_title_badges.js` で `icons/title_<id>.png` に作ります。技能バッジ（`badges`。銅・銀・金・ダイヤ）は今までどおり。
- 畑：投票で「畑」が建つと 6 区画できます。くわで耕す → 種をまく → 何日かで段々に育つ → 収穫。小麦・にんじん・じゃがいも。雨の日と、水路（投票、畑のとなりに建つ）のそばはよく育ちます（`farming`）。
- 動物：ウシ・ヒツジ・ニワトリ・ブタが野原を歩いています。「動物の柵」が建つと近くの動物を連れて来て飼い、ミルク・羊毛・たまご・きのこがもらえます（`animals`）。村人は動物を殺しません。
- やりたい仕事に「漁業」「農業」「牧場」があり、選んだ人はその仕事を多めにします。はじめての魚・宝物・畑・収穫・飼育・たまご などは歴史に残ります。
- 岩の中身（石・石炭・鉄・金・ダイヤ）は `config.json` の `ores` の確率と、種と岩の id で決まります（毎回同じ）。鉄・金・ダイヤを掘ると光り、歴史に「〇〇が鉄鉱石を見つけた。」と残ります。
- 木は決まった回数たたくと倒れ、原木が落ちて切り株が残ります。切り株の場所にはもう生えません。`stumpDays` たつと別の空いた場所に苗木が出て、`saplingDays` で木になります。切り株はたたくと（`stumpDig` の確率で `stumpHits` 回）原木 1 本か「切り株」が落ちて消え、たたかなくても `stumpRotDays` で朽ちて消えます。掘り切った岩は何日かで、同じ所か別の所にまた出ます（`config.json` の `respawn`）。
- 建物（建てる場所も）のまわり `terrain.clearBlocks` ブロック（初め 4）には、木も岩も置かず、生やしません。建物が建つと、まわりの木と岩はどけます。町の外の地形づくりも同じ決まりです。
- 草の畑：草を摘むと、ときどき種が取れます。くわを持った村人は、チェストに種があれば、村のまん中のまわりの草を耕して畑にし、種をまきます（`grass`）。育つと収穫で作物と種が取れます。
- 種や作物を持っている村人には、近くの野の動物（ウシ・ヒツジ・ブタ・ニワトリ）がついて歩きます。柵があれば、その人が 1 頭ずつ柵の中へ連れて入れます（`animals.followRange`）。
- 体力とおなか：どちらも 0〜20（ハート・肉のアイコン 10 個、1 つで 2）。おなかは毎日と働いた分へり、チェストの食べ物を食べると戻ります。おなかが 0 だと体力が少しずつ減ります。死にません。体力が少ない人は次の日休んで戻します（`needs`）。村人ページと、町の画面の村人カードに出ます。
- 村人は歩く前に進む向きへなめらかに体を回し、後ろ向き・横向きには歩きません。木や岩を見るのは、たたいている間だけです。
- 木と岩は地図の全体（町の近くも外も）に、むらなく散らばっています。遠くの木と手つかずの岩はまとめて描く（インスタンス）ので、スマホでも重くなりません。
- 町のまわりの地形は、種（`terrain.seed`）から 16×16 ブロックのチャンクごとに作ります（`js/terrain_gen.js`・`js/terrain.js`）。カメラのまわりだけ作り、遠くなったら捨てます。川・小さな湖・山と丘・砂浜・森の濃さは雑音で決まり、町の広場のまわりは平らです。遠いチャンクほど粗く描き（LOD）、霧で見える距離を区切ります（`viewChunks`・スマホは `viewChunksMobile`）。町の外の木と岩は見た目だけで、村人が切るのは `world.json` の木と岩です。
- 見本のデータの名前は「村人1」「村人2」…で、本当の ID にはなりえない形です。動画には名前を出しません（本物の参加者の名前は今までどおりサイトに出ます）。

## 島の形と、島が広がる決まり

- 町は海にかこまれた小さな「はじまり島」から始まります（半径およそ 50＝約 26 ブロック。前の広い平地の一辺 220 の半分以下）。町の画面を開いた時のカメラに、島ぜんぶがちょうど入ります。広場の予定地・町のチェスト・たき火は島のまん中で、どの向きも岸まで 40 以上あります。ふちは砂浜です。
- 島の形は `data/world.json` の `islands`（`js/island.js` が「どこが陸か」を決める）。0 日目の島は `tools/island_layout.js` が作ります。
- 北の海の向こうに「北の島」があります（はじめは行けない）。フォロワーが `config.json` の `expansion.bridges.north.followers`（初め 50 人）をこえると、チェストの木材と石を毎日少しずつ使って橋を作り始め、`cost` の分がそろうと橋ができます。橋ははじめは無く、作っている間は町の画面で「くいを立てる → 板を少しずつ渡す → 手すり」の順に進みます。次の日から村人の何人か（`workShare`）が北の島で木を切り・岩を掘り、「どこに建てる？」に「北の島の森の入口」が出て家も建てられます。始まった日とできた日は町の歴史と日記に残ります。
- 北東のずっと先に、山と森がある大きな陸がかすんで見えます（名前も札もなく、見えるだけで行けません）。
- 前の広い平地の `world.json`（`islands` がない物）も、そのまま読めて動きます。前の形を作りたい時は `node tools/init.js --legacy`（または環境変数 `TOWN_LAYOUT=legacy`）。

### 町を小さな島で作り直す（住んでいる人は残す）

```
node tools/init.js --keep-villagers
```

新しい小さな島の 0 日目になります。`villagers.json` の村人は印（key・igId）・スキン・最初の道具のまま残り、0 日目の島ですぐ暮らし始めます（`joinExclude` の持ち主は入りません）。`startAt` は変えないので、始める日はいつもどおり決めてください。拠点はまだなく、拠点の場所の投票（下の「拠点の場所は投票で決める」）が始まった形になります。

## 昼と夜・夜の敵

- 町の地図は、本当の時刻（日本時間）に合わせて朝・昼・夕方・夜が変わります。空は高さで色が変わり、四角い太陽にやわらかい光の輪、朝夕は空と霧が赤く、夜は月と星が出ます。影は太陽の向きに合わせます（`js/daynight.js`）。夜は家の窓・扉の横のたいまつ・街灯が光ります。
- 夜、村人は家（家がない人はテント）に帰って寝ます。何人かは町のはずれで、たいまつを持って見張りをします。
- 確かめる時は `?time=morning`・`?time=day`・`?time=evening`・`?time=night`、または `?time=21:30` のように時刻を付けて開きます（例 `index.html?time=night`）。
- 敵は今は出しません（`config.json` の `enemies.enabled` を `true` にすると、コードはそのまま動きます）。出す時は、2 日目の夜から、森の外からゾンビ・スケルトン・クモが来ることがあります。結果は `tools/night.js` が決めて `data/state.json` の `night` と歴史（「夜」）に残します。例：「3日目の夜、ゾンビ 2 体とスケルトン 1 体が来たが、村人1たちが追い払った。」
- ゾンビは破れた服の箱人形で、腕を前に出してよろよろ歩きます。スケルトンは弓を持ち、少し離れて止まって矢を射ます。矢は柵や地面に刺さり、見張りは盾で防ぎます。
- 見張りの力（1 人 2）＋守りの建物の強さ＋たいまつが、来た数より足りないと、小さな被害が出ます（畑がひとつ荒らされる・倉庫の食べ物が少し減る・見張りが軽いケガをして次の日だけ休む）。村人は死にません。朝になるとゾンビは燃え、ほかは森へ帰ります。
- 守りの建物：木の柵（2）・石の壁（4）・見張り台（2）・街灯（1）・見張り塔（3）。合計が大きいほど、静かな夜がふえ、来る数が減ります。木の柵は 10 人、見張り台は 25 人、石の壁・街灯は 100 人の投票で選べ、選ばなかった物もあとで建ちます。
- 夜の乱数は昼とは別なので、夜を足しても昼の仕事・投票・関係の流れは変わりません（ケガで休んだ次の日からは変わります）。

## 最初の道具

- 参加する時に、木の道具を 1 つ選んで持ってきます。それが得意な仕事になり、その仕事を先にします（持ち物 3 枠のうち 1 つを使います）。
- 選び方は参加のコメントに道具の言葉を入れるだけ：「住みたい ピッケル」→つるはし（採掘）、「住みたい 斧」→木こり、「住みたい 釣り」→釣りざお（漁業）、「住みたい くわ」→畑。言葉の一覧は `config.json` の `startTools`。剣（見張り）は敵が出るようになったら選べます。
- 道具の言葉がなければ、村の中で持っている人がいちばん少ない道具が自動で決まります。
- ログインしたあとの村人ページの「最初の道具」で、参加した日の間に 1 回だけ変えられます（0 日目に来た人は 1 日目の終わりまで）。

## 誕生日・好きな食べ物・MBTI（参加のコメント）

- 参加のコメント 1 つに、道具・誕生日・好きな食べ物・MBTI をまとめて書けます。名札はいりません。区切りは空白・`、`・改行のどれでもよい：
  - `住みたい ピッケル 12/11 りんご INFP`
  - `住みたい ピッケル 12月11日 リンゴ`
  - 改行して書いても同じ：`住みたい`⏎`ピッケル`⏎`12/11`⏎`りんご`⏎`INFP`
  - 名札つきでもよい：`住みたい 誕生日 12/11 好きな食べ物 りんご MBTI INFP`・「住みたい 誕生日3月14日 りんご」「住みたい ピッケル 誕生日12月25日 魚」。
- 名札なしで町にない食べ物（「住みたい ピッケル 12/11 カレー」「住みたい カレー」のカレー）も、そのまま好物にします（あとで町に足せばよい）。住みたい・道具・日付・MBTI・あいさつ（よろしく など）・「〇〇さん」の呼びかけ・「です」などを除いて、残った言葉がちょうど 1 つの時だけです（2 つ以上残ったら読まない）。悪い言葉・10 文字より長い言葉・絵文字・URL は使いません。
  - 続けて書いても、日付・住みたい・道具の言葉で区切って読みます：`住みたい12/11カレー`・`住みたいピッケル12月11日カレー`。
- MBTI：16 タイプ（`INFP`・`ENTJ` など）。小文字・全角でもよい。`INFP-T`・`infp-a`・`MBTI INFP` も読みます（A/T は `villagers.json` の `mbtiAT`、タイプは `mbti`）。書いていない人には入れません（誕生日・食べ物とちがう）。URL・`@名前`・`#タグ` の中は読みません。村人ページとカードに「MBTI：INFP-T」と小さく出ます（書いた人だけ）。
  - 出す・出さないは `config.json` の `mbtiOn`（`false` で読まないし出さない。サイトの案内の例からも消える）。
- **住んだあとに変える**：もう住んでいる人は、見ている投稿（「住みたい」の投稿・投票の投稿）に `誕生日 12/11`・`好きな食べ物 りんご`・`MBTI ENFP`（`ENFP` だけでもよい）とコメントすれば、その値だけ変わります。`住みたい 12/11 りんご` でもよい。道具・仕事は変わりません。あとに書いた値が勝ちます。住んだあとのコメントでは、名札のない日付や食べ物は読みません（ふつうの会話を誕生日にしないため。「誕生日おめでとう」も読まない）。
  - 前に入れたコメントの時刻を `villagers.json` の `profileAt` に残し、それより新しいコメントだけを使います（ログインのプロフィールで直した値を、古いコメントで戻さないため）。中身は `tools/people.js` の `applyCommentProfiles`（join.js と sim.js が使う）。
- まだ住んでいない人は「住みたい …」で、住むのと同時に全部入ります。
- 誕生日の書き方：`3/14`・`03/14`・`3-14`・`3.14`・`3月14日`・`3月14`・`0314`・`３月１４日`（全角）・`誕生日3/14`・`誕生日は3月14日`・`たんじょうび 3/14`・`3/14生まれ`。年は読みません（`2000/3/14` は 3/14）。ありえない日（`13/40`・`2月30日`）は読みません。
- 食べ物は町にある物とその言いかえを読みます（りんご・魚（刺身・寿司・フナ…）・木の実（ベリー）・にんじん・じゃがいも（ポテト）・たまご（卵焼き）・ミルク（牛乳）・きのこ・パン・小麦）。「好きな食べ物カレー」「好物は〇〇」のように書けば、10 文字までの安全な言葉はそのまま使います（悪い言葉・URL は使わない）。一覧は `tools/people.js` の `FOODS`。
- 書かなかった人には、名前の印（key）から決まった誕生日と町の食べ物が入ります（同じ人はいつも同じ。乱数なし）。入れるのは「住みたい」で来た人（`source: comment`）だけで、ある値は変えません（足すだけ）。あとのコメントで書いた値は、前の値（自動で入った値も）を置きかえます（上の「住んだあとに変える」）。
- 誕生日は `villagers.json` の `birthday`（`MM-DD`）、食べ物は `profile.food`。村人ページのプロフィールに出て、誕生日の日は町の歴史に「お祝い」が出ます。

## 最初の日

本番の 0 日目は、木と岩だけの平地です（村人 0 人・建物 0・道 0。たき火もありません）。フォローして「住みたい」とコメントした人が、すぐ村人になります。
村人が 0 人の間は、どの画面にも「まだだれもいません。フォローしてコメントに『住みたい』で、すぐ村人に」と出ます。

## 町を始める日（0 日目 → 1 日目）

町は、持ち主が「始める」と決めるまで 0 日目のままです。0 日目のあいだも「住みたい」の人はすぐ住み始めます（島を見て回り、夜はテントのそばで寝ます）。毎朝の daily は動きますが、日は進めません。
町の画面には「町はまだ始まっていません（0日目）」と出ます。始まる日時を決めていれば「11月28日 6時から1日目が始まります」のように出ます。

始め方は 2 つ（どちらか 1 つでよい）：
1. **日時を決めておく**：`data/config.json` の `"startAt": null` を `"startAt": "2026-11-28 06:00"` のように書きかえてコミットする（日本時間。日だけ `"2026-11-28"` なら朝 6 時）。その時刻を過ぎた最初の朝の daily（6 時）で 1 日目になります。
2. **今すぐ始める**：GitHub の Actions タブ → daily →「Run workflow」→ `start` にチェックを入れて「Run workflow」を押す。その場で 1 日目になります。
- 1 日目の日付は、始めた日（日本時間）になります。そのあとは毎朝 6 時にふつうに 1 日ずつ進みます。
- 0 日目に戻したい時（本番の前に作り直す時）：Actions タブ → reset →「Run workflow」→ `confirm` に「0日目にする」と入れて押す（`tools/init.js` を動かして、村人 0・木と岩だけにする）。手元なら `node tools/init.js` のあと `data/` をコミットする。戻したあと、`startAt` がもう過ぎた日時のままだと次の朝すぐ始まるので、`null` か新しい日時にしてください。
- 手で `node tools/sim.js` を動かす時（見本・テスト）は、0 日目でもそのまま進みます。止めるのは daily.yml の `--gate` だけです。

## 拠点の場所は投票で決める（0 日目）

「まず拠点（町のチェスト・たき火・広場を置く所）の場所を決めてから、建物を建てる」ための決まりです。

- 本番の 0 日目（`node tools/init.js`、`--keep-villagers` も）には、拠点がまだありません。地図に候補の旗 **A 浜辺の近く・B 池のそば・C 森の入口** と、今の票の札が出ます。地図の上に「拠点の場所を投票中！ コメントに A・B・C のどれかを書いてね」の帯が出ます。
- 村人はテントで寝て、島を見て回ります（チェスト・たき火・建物はまだ）。
- 投票は、投票の投稿（Secrets の `IG_VOTE_MEDIA`）へのコメントで数えます。「A」「ａ」「Ａ」「Aがいい」のほか、場所の名前（「浜辺」「池」「森」など、`config.json` の `baseVote.candidates[].words`）でも読みます。1 人 1 票で、何度か書いたら最後のコメント。2 つ書いたものは数えません。町のアカウントの持ち主（インスタから読んだ自分の名前と `joinExclude`）は数えません。
- 票は 15 分ごとの受付（`join.js`）で数え直して、町の画面と投票のページに出します。
- **決まる時**：1 日目にする朝（`startAt` か、Actions の daily を `start` で動かした時）。`config.json` の `baseVote.until` に日時（例 `"2026-11-28 05:00"`）を書くと、その時刻で締め切り、そのあと最初の受付で決まります（0 日目のうちに拠点ができる）。
- いちばん票の多い場所に決まります。同点や票がない時は `baseVote.fallback`（初め `B`）の場所（同点の中にあれば）にし、そのことを歴史に書きます。
- 決まると：その場所にチェスト・たき火・広場（1 日目に整地）を置き、まわりの木と岩をどけます。テントも拠点のそばへ移ります。家や建物の区画（半径 12・19・26 の輪）・道・「どこに建てる？」の候補は、拠点のまわりになります。歴史に「拠点が「C 森の入口」に決まった（A 2票・B 0票・C 3票、5 人が投票）。」のように残り、みんなの日記にも書かれます。結果は投票のページの「これまでの投票」に出ます。
- 候補の名前（`name`）・読む言葉（`words`）・説明（`desc`）は `config.json` の `baseVote` で書きかえられます。`x`・`z` は地図の位置です（変えるなら島の陸の上、岸から 15 以上、池から 14 以上、候補どうし 20 以上はなす）。今は A が南の砂浜の手前、B が西の池のとなり、C が北の森の手前で、3 つは 45 以上はなれています。
- 家のない村人は、たき火のうしろの大きいテント（`config.json` の `tent`。1 つに `perTent` 人、`maxTents` まで）の中の敷物で寝ます。ベッドを作った人は、テントの中（家ができたら家の中）にベッドを置きます。ベッドを外に置くことはありません。テントがいっぱいの時は、たき火のそばで横になります。テントは羊毛ブロックと原木で組んだ段々の三角屋根で、前の面のまん中に入口があり、村人は入口から出入りします（夜は中にランタンがともり、カメラを近づけて上から見ると屋根が半透明になって、中で寝ている人が見えます）。`enabled` を `false` にすると、前と同じく島のまん中に拠点を置きます。見本（`--demo`）・前の形（`--legacy`）・`--fixed-base` の時も島のまん中です。
- 投稿の文と固定コメントの下書きは `docs/インスタ文章.md` の「拠点の場所の投票」。拠点が決まったら、次の「何を建てる？」の投稿を作って、その URL を Actions の「投稿の URL を変える」で貼ってください（下の「投稿の URL を変える」）（1 日目の「何を建てる？」は、拠点を締めた時刻より前のコメントは数えません）。
- 前の町（拠点の投票がない `world.json`）は、今までどおり島のまん中（`square`）が拠点のまま動きます。

## 参加の登録（コメント）

- 投稿に「住みたい」「すみたい」を含むコメント（前からの「住みたい」「参加します」「参加」も受け付けます）をした人が、**その場で**（15 分ごとの受付 `join.yml` で、15〜30 分ほどで）町に住み始めます（言葉は `config.json` の `joinWord`）。次の朝を待ちません。0 日目でも同じです。
- 住み始めた時に、その日の日記の 1 行目（「今日から村に住むことになった。よろしく。」）・町の歴史・最初の道具・家（なければたき火のそばのテント）ができます。その日は村を見て回り、次の朝からふつうに働きます。
- フォローしてからコメントしてね、とお願いしています。ただしインスタの API では、コメントした人がフォローしているかは確かめられないので、コメントだけでも住めます。
- 町のアカウントの持ち主（インスタから読んだ自分の名前、`config.json` の `joinExclude` に書いた名前）は村人になりません。
- 前の言葉「住民登録」も、念のため読みます。「参加しない」「参加できない」「不参加」は登録にしません。
- 同じ人が何回コメントしても 1 回だけ。見分けはコメントの `from.id`（インスタの固定の ID）です。
- 名前（username）が変わっていたら、名前だけ新しくします。参加日やスキンはそのままです。
- スキンは村人の番号から決まるので、名前が変わっても見た目は変わりません。
- インスタの ID と名前は、そのままではなく印（sha256）にして `villagers.json` に入れます。

## 投票（コメント）

- 投票中の投稿へのコメントから A・B・C を読みます。全角（Ａ）、小文字（a）、「Aがいい」「B案」も読みます。「BとCで迷う」のように 2 つ書いたものは数えません。
- 1 人 1 票で、何度か書いた人は最後のコメントだけ数えます。受け付けの時刻（`state.json` の `votes[].opensAt`〜`closesAt`）の外のコメントは数えません。
- 手で票を足したい時は `state.json` の `votes[].manual` に `{"A": 3, "B": 0, "C": 1}` のように書きます（コメントの票に足されます）。
- 結果は `state.json` の `decisions` と `history.json` に残り、投票のページに割合の棒グラフ、投票した人数、時間ごとの伸び（折れ線）、過去の結果が出ます。

## フォロワー一覧の取り込み

インスタの公式 API ではフォロワーの一覧は取れません。代わりに、アカウントの持ち主が自分の情報をダウンロードして取り込めます。

1. インスタのアプリで「設定とアクティビティ」→「アカウントセンター」→「あなたの情報とアクセス許可」→「個人情報をダウンロード」を開く。
2. 「情報をダウンロードまたは転送」→ インスタのアカウントを選ぶ →「一部の情報」→「フォロワーとフォロー中」だけにチェック。
3. 「デバイスにダウンロード」で、形式は **JSON**、期間は「全期間」にしてリクエストする。
4. 準備ができるとメールが届く（数分〜数日）。zip を開くと `connections/followers_and_following/followers_1.json` がある。
5. それを `data/import/` に置いて `node tools/import_followers.js` を動かす。まだいない人だけが次の日から村人になります（名前で見分けるので、何度取り込んでも重複しません。こちらはコメントとちがい、次の日からです）。

`data/import/` と `data/inbox/` は全員の名前が入るので、`.gitignore` で GitHub に上がらないようにしてあります。

## 名前を出したくない人

```
node tools/hide.js ユーザー名
```

`data/hidden.json` に名前から作った印（`sha256:…`）が書かれ、その人は「のんびりなタヌキ」のような自動のあだ名で表示されます。`villagers.json` からも名前が消えます。`hidden.json` に名前をそのまま書いても動きますが、公開されるので印にするのがおすすめです。

## GitHub に出す

1. GitHub で新しいリポジトリを作る（例：`minna-no-machi`。`ユーザー名.github.io` にすればトップの URL になる）。
2. このフォルダ（`town/`）の中身をリポジトリのいちばん上に置いて push する（`node_modules/` は `.gitignore` 済み）。
3. リポジトリの Settings → Pages →「Deploy from a branch」→ `main` / `/(root)` を選ぶ。
4. 本番を始める時は `node tools/init.js` で村人なしの 0 日目に戻してから push する（見本のままでもよい）。`data/config.json` の `account` を自分のアカウント名にする。

## インスタとつなぐ（GitHub Actions で毎日動かす）

`.github/workflows/daily.yml` が下書きです。今は手で動かす時だけ動きます。

1. インスタを **プロのアカウント（ビジネス or クリエイター）** にし、Facebook ページとつなぐ。
2. Meta for Developers でアプリを作り、「Instagram Graph API」を足す。権限は `instagram_basic`、`instagram_manage_comments`、`pages_show_list`、`pages_read_engagement`。
3. Graph API エクスプローラで、つないだインスタの ID（`IG_USER_ID`）と長期アクセストークン（`IG_TOKEN`、60 日で切れるので更新が要る）を取る。
4. 「住みたい」を集める投稿の ID（`IG_JOIN_MEDIA`、複数ならカンマ区切り）と、今の投票の投稿の ID（`IG_VOTE_MEDIA`）を調べる（`/{IG_USER_ID}/media` で一覧が出る）。
5. GitHub のリポジトリの Settings → Secrets and variables → Actions に、上の 4 つを入れる。合言葉はファイルに書かない。
6. Actions タブから daily を手で 1 回動かして、緑で終わるか見る（0 日目のあいだは、start を選ばなければ日は進みません）。よければ `daily.yml` の `schedule` の `#` を外す。

投票が開いたら（投票のページに出る）、その投稿を作って、下の手順でその投稿の URL を町に教えます。

### 投稿の URL を変える（スマホでも・URL を貼るだけ）

投稿の ID を調べなくても、インスタの投稿の URL を貼れば町がその投稿を読みます。

1. インスタで投稿の「…」→「リンクをコピー」。
2. GitHub アプリ（またはブラウザの github.com）でこのリポジトリ →「Actions」→「投稿の URL を変える」→「Run workflow」。
3. 「投票の投稿の URL」か「住みたいの投稿の URL」にコピーした URL を貼り、「Run workflow」。
4. 緑のチェックになれば、`data/config.json` の `votePostUrl` / `joinPostUrl` が書きかわってコミットされています。次の受付（15 分ごとの join）から、その投稿のコメントを数えます。投票のページ・町の画面の投票のボタンも新しい投稿へのリンクになります。

- 住みたいの投稿は**足していく**ので、前の投稿の「住みたい」も受け付けつづけます（`joinPostUrl` は文字 1 つでも `["URL1", "URL2"]` のならびでもよい）。
- 「消す」と書くと空に戻します（空のあいだは Secrets の `IG_VOTE_MEDIA` / `IG_JOIN_MEDIA`、それもなければ最近の投稿）。
- しくみ：`tools/instagram.js` がアカウントの投稿の一覧（`/{IG_USER_ID}/media` の `permalink`、新しい順に最大 500 件）を読み、URL の「短いコード」（`/p/` や `/reel/` の次の文字）が同じ投稿の ID を使います。`www` の有無・`?igsh=…`・最後の `/`・`/reel/` と `/p/` のちがいは気にしません。見つからない時は Actions のログに「見つかりません」と出て、Secrets の ID を使います。
- 貼った URL の投稿が見つかるかは、Actions の `ig_check` でも確かめられます。

### PC を付けていなくても町を進める（毎日の自動）

今は `daily.yml` の `schedule` が `#` で止めてあり、Actions タブから手で動かした時だけ進みます。GitHub の上で動くので、外せば PC を付けていなくても町は毎日進みます。

**外す手順**
1. 先にリポジトリへ出しておく（GitHub Pages も使うなら Settings → Pages で公開する）。
2. Settings → Secrets and variables → Actions に、下の Secrets を入れる（使わない物は入れなくてよい）。
3. Actions タブ → daily →「Run workflow」で 1 回手で動かし、緑で終わり、`data/` のコミットが 1 つ増えるのを見る。
4. `.github/workflows/daily.yml` の次の 2 行の先頭の `# ` を消してコミットする。
   ```yaml
   schedule:
     - cron: "0 21 * * *"   # 毎朝 6 時（日本時間）
   ```
   cron は世界標準時です（`0 21 * * *` ＝日本時間の毎朝 6 時）。GitHub が混んでいると数分〜数十分おくれることがあります。また、60 日間リポジトリに動きがないと、GitHub が schedule を止めます（毎日コミットされるので、ふつうは止まりません）。

**外すと毎朝自動で動くこと**（上から順に）
1. **インスタを読む**（`tools/instagram.js`）：フォロワー数と、参加の投稿・投票の投稿のコメントを読み、`data/inbox/instagram.json` に書く。DM で招待リンクを送る部分は、今は `DM_READY = false` なので送らない。
2. **Firestore を同期する**（`tools/firestore_sync.js`）：Google ログインのつなぎ（uid と村人の ID だけ）と、本人が書いたプロフィール・見た目を取り込む。`FIREBASE_SERVICE_ACCOUNT` が空なら何もせずに終わる。
3. **住む人の受付**（`tools/join.js`）：「住みたい」の人をその場で町に迎える。
4. **町を 1 日進める**（`tools/sim.js --gate`）：投票の集計・仕事・建物・関係・夜の敵など。0 日目のあいだは、始める時（`startAt` を過ぎた・`start` を選んだ）だけ進む。
5. **結果をコミットして push する**：`data/` の json と日記のファイル（`data/diary/`）。GitHub Pages を使っていれば、サイトもそのまま新しい日になる。

15 分ごとの `join.yml` は、インスタを読む → 住む人の受付（その場で入居）→ 変わったファイル（村人・暮らし・日記・歴史・関係・地図）をコミット、だけをします。日は進めません。

- 「住みたい」と誕生日・好きな食べ物・MBTI は、**最近の投稿（`config.json` の `joinScanPosts`、既定 25 件・`joinScanDays` 既定 60 日まで）のどれに書いてもよい**。`joinPostUrl` の投稿は古くても読みます。投票（A・B・C）は投票の投稿のコメントだけで数えます。
- join はコメントの数が前と同じ投稿を読みません（Actions のキャッシュに、投稿ごとの数だけを覚えておく。名前やコメントは入れない。6 時間に 1 回は全部読み直す）。
- コメントがついたら 2〜3 分で反映したい時は **`docs/すぐ反映する手順.md`**（Cloudflare の受け口 `tools/webhook/` から `repository_dispatch` で join を動かす）。

**要る Secrets の名前**
| 名前 | 中身 | 無い時 |
|---|---|---|
| `IG_TOKEN` | インスタの長期アクセストークン（60 日で切れる） | インスタを読まずに進む |
| `IG_USER_ID` | インスタのプロのアカウントの ID | 同上 |
| `IG_JOIN_MEDIA` | 「住みたい」を集める投稿の ID（カンマ区切りで複数可）。`config.json` の `joinPostUrl` があればそちらが先。どちらも最近の投稿（`joinScanPosts`）に足して読む | 最近の投稿だけ読む |
| `IG_VOTE_MEDIA` | 今の投票の投稿の ID。`config.json` の `votePostUrl` があればそちらが先 | いちばん新しい投稿で数える |
| `FIREBASE_SERVICE_ACCOUNT` | Firebase のサービスアカウントの鍵の JSON（Google ログインを使う時だけ） | Firestore の同期をとばす |

`GITHUB_TOKEN`（コミットと push に使う）は GitHub が自動で用意するので、入れなくてよいです（`permissions: contents: write` で許してあります）。

## Google ログイン（プロフィールを自分で書きかえる）

村人ページの「プロフィール」で、Google でログインした本人だけが自分の村人のプロフィールを書きかえられます。Firebase Authentication と Firestore の無料枠で動きます。`js/firebase-config.js` が空のあいだは、ボタンが「Google でログイン（準備中）」になるだけで、サイトはそのまま動きます。

**保存するもの**：Google アカウントの `uid` と、結びつけた村人の key だけ。メールアドレスや名前は読みこまず、保存も公開もしません。

### つなぎ方 1（主）：DM の招待リンク

Instagram のログイン API は、プロの（ビジネス・クリエイターの）アカウントしか使えません。普通の人に Instagram でログインしてもらって名前を受け取ることはできず、Google ログインからインスタの名前を知ることもできません。そこで、コメントした人に DM でリンクを送ります。

1. 「住みたい」とコメントする。
2. 毎日の処理で村人になったあと、`tools/firestore_sync.js` がその人専用の招待の印（20 字・7 日で切れる・1 回だけ）を Firestore の `invites` に作り、Instagram の **Private Replies**（コメントした人に 1 回だけ DM を送れる仕組み）でリンク（`villager.html?k=村人&invite=印`）を送る。
3. リンクを開いて Google でログインすると、コードを打たずにそのまま村人とつながる（使った印は毎日の処理が消す）。

要るもの・注意：
- 権限 `instagram_manage_comments` と `instagram_manage_messages`。どちらも **Meta のアプリ審査** が要ります。
- Private Replies は、コメントから 7 日以内に、1 つのコメントへ 1 回だけ送れます。
- `config.json` の `siteUrl` に公開したサイトの URL を入れる（リンクに使う）。
- いまは `tools/instagram.js` の `sendPrivateReply` は形だけで、本物の API にはつないでいません（`DM_READY = false`）。審査が済んだら `DM_READY` を `true` にし、中の fetch の行を戻してください。
- DM を送れない時や、審査が済むまでの間は、下の「つなぐ」コードの方法を使います。
- 処理は毎日の更新に入っています。DM を早く届けたい時は、daily を数分おきに動かす別のワークフローを足してもよいです（村人になるのは 15 分ごとの受付 `join.js` が動いた時です）。

### つなぎ方 2（予備）：「つなぐ」コード

1. 村人ページで「Google でログイン」を押す。
2. 一度だけ使える短いコード（例「つなぐ 7K3Q」）が出るので、コピーして **インスタの「住みたい」の投稿にコメント** する。
3. 次の毎日の処理で、コメントした人の `from.id` が参加の登録をした人と同じかを確かめ、その Google アカウントと村人を結びつける（コードは消す）。
4. それからは、ログインすると入力欄が出て「保存」できる。次の毎日の処理で町に反映される。

ほかの人のコードをコメントしても、コメントした本人の村人に結びつくだけなので、他人の村人は乗っ取れません。1 つの村人に結びつくのは最後の 1 人だけです。

### 用意（最初に 1 回）

1. https://console.firebase.google.com/ でプロジェクトを作る（Google アナリティクスは不要）。
2. 「Authentication」→「ログイン方法」で **Google** を有効にする。「設定」→「承認済みドメイン」に GitHub Pages のドメイン（`ユーザー名.github.io`）を足す。
3. 「Firestore Database」を作る（本番モード、場所は `asia-northeast1` など）。
4. 「ルール」に、このリポジトリの `firestore.rules` の中身を貼って公開する（または `npx firebase-tools deploy --only firestore:rules`）。
5. 「プロジェクトの設定」→「マイアプリ」でウェブアプリを足し、出てきた `apiKey` / `authDomain` / `projectId` / `appId` を `js/firebase-config.js` に入れる。これらは公開されても大丈夫な値です（守りはルールで行います）。
6. 「プロジェクトの設定」→「サービス アカウント」→「新しい秘密鍵を生成」で JSON をダウンロードし、**中身をそのまま** GitHub の Secrets に `FIREBASE_SERVICE_ACCOUNT` という名前で入れる。ファイルはリポジトリに入れず、入れたら手元からも消す。
7. Actions の daily を手で動かすと、`tools/firestore_sync.js` が「つなぐ」コメントを処理し、プロフィールを `data/villagers.json` に入れる。手元で試すなら `FIREBASE_SERVICE_ACCOUNT='（JSON）' node tools/firestore_sync.js --dry`（書きこまずに結果だけ出す）。

### プロフィールの項目（`data/config.json` の `profileFields`）

項目は定義から入力欄と表示を自動で作ります。1 つの項目に書けるもの：

| キー | 意味 |
| --- | --- |
| `id` / `label` | 項目の名前と、画面に出す名前 |
| `type` | `select`（`options` から選ぶ）・`text`・`number`（`min` / `max`）・`monthday`（月日）・`date`・`color` |
| `public` | `true` なら村人ページに出す。`false` なら本人だけが見られ、`data/` には入れない |
| `effect` | 町への効き方。`personality`（性格・相性）・`birthday`（お祝い）・`accent`（服の差し色）・`job`（仕事の割り当て） |
| `max` | 文字の上限（`text`） |

自由に書ける欄は、悪い言葉・リンク・@ を弾き（`js/profile-fields.js`）、ページに出す前に必ずエスケープします。毎日の処理でも同じ確かめをもう一度してから反映します。

**項目を足したり変えたりしたら、`firestore.rules` の `profiles` の `hasOnly([...])` と各項目の確かめも合わせて直してください。**（公開しない項目は `private` の `hasOnly` に足す）

### 予備：コメントで送る

ログインを使わなくても、村人ページの「コメントで送る」で「プロフ INFP 0512」のような文を作り、「住みたい」の投稿にコメントすれば、MBTI と誕生日（月日）だけは反映されます。`config.json` の `profileForm.url` に Google フォームなどの送り先（`{text}` が文に置きかわる）を入れると、フォームへのボタンも出ます。

## スキンについて

`tools/gen_skins.js` が髪型・髪色・肌・目・眉・口・服（シャツ・上着・ズボン・靴）・小物（帽子・めがね・エプロン・マフラー・うで時計）を組み合わせて、64×64（マイクラのスキンと同じ配置）で作ります。既存のスキンは使っていません。

見た目の決まりは `js/skingen.js` にあり、シード（数）と体の種類（男性・女性・指定なし）から同じスキンが決まります。肌・髪型と髪色・目・服（上・下・靴の形と色と柄）・帽子と小物がシードで決まり、色は合う組み合わせの表から選びます。女性は髪が長め・スカートやワンピース・細い腕（3px）になることがあります。ふだんの村人は「指定なし」で、シードはスキンの番号です。

- 最初のスキンは参加した時に自動で決まります（今までどおり名前の数から）。
- ログインした本人は、村人ページの「見た目」で体の種類（男性・女性・指定なし）を選べます。体の種類を変えた時だけ、「別のを引く」で 1 回だけ引き直せます。引き直した後のボタンは「引き直しは使いました」になり、押せません（`profileFields` の `look`、`体:シード:回数` の形で保存）。
- 引き直した回数は、Firestore のプロフィールと `villagers.json` の `lookRerolls` に残ります。sim は `lookRerolls` を見て 2 回目を断るので、ページを開き直しても回数は戻りません。
- 「体型」（`profileFields` の `body`）で、通常と 2 頭身を選べます。何度でも変えられ、引き直しの回数とは別です。sim が取り込んで `villagers.json` の `body: "normal" | "chibi"` とプロフィールの `body` に入れ、町の画面・村人ページ・動画はその体型で描きます。`?chibi=1` を付けると、全員を 2 頭身で試せます（`js/character.js` の `chibiOf`）。
- `skins/見本24.png` は男性・女性・指定なしを 8 体ずつ並べた見本です。

## 何人まで参加できるか（測り方と軽量化）

`node tools/bench.js --out <作業用フォルダ> --n 50,300,1000 --days 2` で、作業用フォルダに見本の町を作って測ります（本物の `data/` はさわりません）。1 日分の sim の時間、`data/*.json` の大きさ、町の画面のコマ数（そのままと CPU 4 倍の制限）を出します。`--mobile` を付けるとスマホの画面（390×844）で、はじめから CPU 4 倍の制限をかけて、開くまでの時間とコマ数を測ります。`--reuse` は作った町を使い回して画面だけ測り直します。

### 地図はマスの文字で持つ（`js/tilemap.js`）

- 地図は「1 マス（1 ブロック）＝1 文字」で、16×16 マスのチャンクごとに 16 行の文字列にしています。文字は `g` 草・`t` 木・`p` 苗木・`u` 切り株・`x` 掘り出した跡・`r` 岩・`o` 掘り切った岩・`w` 水・`s` 砂・`q` 村のまん中・`b` 建物・`f` 畑・`k` 草むらです（町の外の山 `m` などは、地形のノイズからその場で決めます）。
- `data/world.json` には、この文字列をランレングス圧縮（`12g3t` ＝草 12 マス・木 3 マス）して入れます。ふつうの木と岩（形・向き・大きさがマスから決まる物）は文字だけで、ちがう所がある物だけ `objs` に残します。読む時は `tools/store.js`（sim・テスト）と `js/common.js`（サイト）で、いつもの `trees`・`rocks` の一覧に戻します。
- 木・岩・畑・空き地さがし（sim.js の苗木・岩の生えかわり・近い木と岩・建物のまわりを空ける）は、全部の物を調べずに、マスごとの一覧（空間ハッシュ）で周りのマスだけを見ます。
- 村人と動物の位置も、8×8 ブロックのマスごとの一覧で持ちます（動いてマスが変わった時だけ付け替えます）。sim.js の関係の「近い人」、町の画面の「ぶつからないように避ける」「動物がついて行く人」「ちゃんと描く人と名札の人」「画面に入っているか（マスごとに調べる）」は、周りのマスだけを見ます。プロフィールなどの中身は今までどおり人ごとのデータです。
- 描く時は、地面も木・岩もチャンクごとに 1 つのメッシュにまとめます（見えない面は作りません）。
- 日記と持ち物の枠（locks）は `data/diary/00.json`〜`63.json` の 64 組に分けます（村人の key から組を決める。`js/datafiles.js`）。村人のページを開いた時に、その人の組の 1 ファイルだけ読みます。人ごとに 1 ファイルにすると 3,000 人で書き込みが遅くなるため、組にまとめています。`life.json` には最後の 1 行（`diaryLast`）だけ残ります。

### スマホは最初から軽い設定

小さい画面や指で操作する機械では、最初から 画素の倍率 1・影なし・描く距離 4 チャンク・ふちのなめらかさなし・ちゃんと描く村人 24 人まで で始めます。`?lite=1` で PC でも軽い設定、`?lite=0` でスマホでもふつうの設定になります。three.js は小さくした版（`three.module.min.js`）を読みます。

人が多い時の軽量化：
- 関係（`tools/social.js`）：200 人を超えたら、全員の組を見ずに「同じ家・同じ仕事で近い人・前から関係のある人」の組だけを見ます。何もない組は残しません。
- 町の画面：ちゃんとした姿で描くのは、画面に入っていてカメラに近い 60 人（スマホは 30 人）まで。遠い人は色の付いた簡単な形をまとめて描き、画面の外の人は動きを 4 コマに 1 回だけ進めます。名札もちゃんと描く人だけです。
- 遅い機械では、描く細かさ（画素の倍率）を自動で下げます（`?res=fixed` で止められます）。

## 画面の大きさの決まり

ボタン・カード・表の角の丸み・内側の余白・高さは `css/style.css` の `:root` の変数（`--radius`・`--radius-s`・`--pad-card`・`--pad-x`・`--ctl-h`・`--nav-w`・`--nav-h`）でそろえます。上の 6 つのボタン（町・歴史・投票・村人・関係・スキン）は、どのページでも同じ幅と高さで、文字はまん中です。
